# 0011 Desktop rebrand

## Goal

The desktop app wears the same identity as the website, so a screenshot of the app and one of the web read as one product.
Every window, icon and notification of the Windows app is redesigned with `packages/brand`, and the result ships to users as a new desktop release through the updater.

## Scope

- `apps/desktop` consumes `packages/brand` (tokens, fonts, mark, waveform, primitives, `OverlayPill`); the app's own CSS keeps only layout that the tokens cannot express.
- Icons: tray icon (idle, recording, error or signed-out states, legible at 16 px on light and dark taskbars), app icon, installer icons and the uninstall entry, generated from the brand masters.
- Windows redesigned: sign-in, onboarding (language, dictation languages, default style), settings, the editors (dictionary, styles, default style, app rules), history, the update window and the about view; real empty, loading and error states.
- Overlay: the "Escuchando" or "Listening" pill with the brand waveform driven by the real level, at the size and position 0008 settled.
- Notifications and tray menu copy follow the brand voice, Spanish and English, UI language from Windows with English fallback and a manual override, as 0008 built it.
- Light and dark following Windows, with the manual switch the web has.
- Release: a new minor version (0.2.0) cut with `pnpm release:desktop` from the task branch after the review is clean, published by `desktop-release`, verified as an update from 0.1.1 on Windows.
- Screenshots of every window and state at its real size, light and dark, Spanish and English, refreshed every round, in `.workspaces/0011_desktop_rebrand/screenshots/`, plus side-by-side pairs with the matching web pages.

## Out of scope

- New desktop features or behavior changes.
- The website (done in 0010), except fixing a shared primitive in `packages/brand` when the desktop exposes a bug in it.
- macOS and Linux builds.

## Acceptance

1. Root `pnpm lint`, `typecheck`, `test` pass; `ci`, `desktop-ci` windows and linux-check green on the PR.
2. `apps/desktop` contains no hard-coded colors, font families, font sizes, spacing, radii, shadows or durations outside `packages/brand` tokens (a test enforces it, like the web's).
3. The tray icon reads at 16 px on light and dark taskbars in every state (screenshots), and every window passes WCAG AA in both themes with visible focus and full keyboard reach.
4. Side-by-side screenshots (desktop window next to the matching web page) show the same mark, type, color and voice.
5. Release 0.2.0 is published as latest; an installed 0.1.1 updates itself to 0.2.0 on Windows and the landing's download button shows 0.2.0.
6. RAM and CPU of the idle app stay within 10 MB and 1 point of 0008's measurements (fonts and assets bundled, nothing loaded from the network).
7. Every behavior from 0008 keeps working (its tests unchanged in assertions); a real dictation on Windows still pastes.

## Approach

- Reuse `packages/brand` as is, adding to it only what both surfaces need; alternative rejected: a desktop copy of the tokens, which breaks the one-brand requirement.
- Fonts bundled into the app, no network at runtime.
- Icons generated by the brand's asset script, outputs committed.

## Database

None.

## Infra

- No AWS changes. The release uses the existing `desktop-release` workflow and updater signing secrets.
- Windows runs follow the 0008 machine rules: own mirror `C:\dev\tmw-0011` and scratch `C:\dev\tmw-0011-*`, injected runs only when Sebastian is away, `computer busy` and `computer free` announced through the om-manager, clipboard snapshotted and restored, never touch or read a window the run did not open, removed at clean.

## Design

Direction A "Tinta" from 0010 (Fraunces and Instrument Sans, terracotta on paper, the quotation mark turning into three bars). Design delegated by Sebastian to the om-manager; hard requirement: web and desktop share the same essence.

## Risks

- WebView2 font rendering differs from browsers; compare against the web screenshots.
- The update from 0.1.1 is the first real one; if it fails, users stay on 0.1.1 until fixed.
- Fonts and assets could raise RAM; Acceptance 6 guards it.
