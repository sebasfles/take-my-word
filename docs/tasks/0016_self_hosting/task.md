# 0016 Run your own Take My Word

## Goal

Anyone who does not want to pay for a dictation subscription can run Take My Word in their own AWS account, with their own Groq and OpenAI keys, from this open-source repository.
The landing invites them to do it, the repository holds nothing specific to the official deployment, and the official desktop installer works with any self-hosted server.
Ships in desktop 0.3.0, which this task cuts.

## Scope

- Reusable code and infrastructure: every per-deployment value (AWS account, region, profile, domain and Route 53 zone, Terraform state, GitHub owner and repo, release URLs, updater public key, deploy roles, e2e users) leaves the code and Terraform.
  It comes from one deployment config file that is gitignored, plus GitHub Actions variables for CI.
  A committed example file documents every key.
  After this task, `git grep` finds no trace of the official account, domain, GitHub owner or SSO profile outside `docs/tasks/`.
  The official deployment keeps working from its local config and its repository variables, and its Terraform state is untouched.
- A `self-host/` folder at the repo root, the single place for running your own (Sebastian, 2026-10-22):
  - `self-host/README.md`: prerequisites and dependencies (AWS account, Route 53 domain, Groq and OpenAI keys, Node, pnpm, Terraform, AWS CLI, Claude Code for the skill), then a step-by-step guide, small steps, including updating and removing everything;
  - a Claude Code skill (`self-host/skill/` with a `SKILL.md`, plus how to install it into `.claude/skills/`), the recommended path: an agent reads the repo and walks the person through the setup, asking only what it needs and running the same steps as the command;
  - the setup command, the manual path for people without an agent.
- Setup command (`pnpm selfhost`, documented as the alternative to the skill), idempotent and re-runnable for updates:
  - it asks for the AWS profile, the region, a domain with a Route 53 hosted zone, and the Groq and OpenAI keys;
  - it asks which environments to create, prd only by default and dev optional;
  - it creates the state bucket, applies Terraform, builds and uploads the Lambda code and the web, creates the first user and prints the URLs and that user's temporary password.
  Secrets go to the stores the infra already uses, never to the repo or to tfvars.
- Discovery for clients: every deployment serves `https://<domain>/.well-known/take-my-word.json` with the API URL, region, user pool and client ids. Its schema lives in `packages/shared`.
- Desktop: the official prd app gains "Use your own server" on the sign-in step. It is a small secondary link at the start of the flow, not a prominent option. The user enters a domain; the app reads the discovery file, validates it, keeps it, and signs in against that server. Signing out offers a return to the official server. Updates still come from the official releases.
  This supersedes the ARD entry of 2026-10-21 "Dev and prd are separate apps chosen at build time" for the server choice; dev and prd remain separate apps.
- Landing: a "Run your own" section. It says it is open source (MIT) and runs in your own AWS account, shows the steps with the skill first, and links to `self-host/` on GitHub. It shows the real cost (Sebastian, 2026-10-22): AWS about 0.50 USD per month for the Route 53 zone plus cents, Groq whisper-large-v3-turbo 0.04 USD per audio hour, OpenAI gpt-5.4-nano 0.20/1.25 USD per 1M tokens, an example month at 15 minutes of audio a day, and a note that Groq's free tier and OpenAI complimentary tokens can bring providers to zero; list prices dated, with links. The same numbers go in `self-host/README.md`. Spanish and English, in the 0010 design.
- SEO, as complete as possible (Sebastian, 2026-10-22):
  - `robots.txt` and `sitemap.xml` generated by the web app, with the public pages in es and en, `lastmod`, and the sitemap linked from robots;
  - canonical URLs, `hreflang` alternates for es and en and `x-default`, one language per URL so both are indexable;
  - per-page titles and descriptions, Open Graph and Twitter cards (already from 0010) checked on every public page;
  - JSON-LD: `SoftwareApplication` (name, operating system Windows, price 0, download URL, version from the latest release), `WebSite`, `Organization` or `Person` for the author, and `FAQPage` for a short FAQ section on the landing (what it is, privacy, cost, how to run your own);
  - sign-in, account and every private page `noindex` and out of the sitemap;
  - semantic HTML (one h1 per page, landmarks, alt text), fast Core Web Vitals (0010's Lighthouse bar), Lighthouse SEO 100 on the public pages;
  - self-hosted deployments are `noindex` by default (a config flag), so copies never compete with the official site; the official deployment is indexed;
  - validation evidence in the PR: Lighthouse SEO, the Rich Results test or schema validator output for the JSON-LD, and the robots and sitemap responses from dev.
- Docs: a root `README.md` (what it is, screenshots, a visible "Run your own" part that recommends the skill over the command and links to `self-host/`, license), short.
- Verification: a clean self-host run into a scratch AWS account or a scratch domain prefix of the official account, done by the crew. It goes from a fresh clone to a dictation from the official 0.3.0 app pointed at it, then it is torn down with the documented removal step.

## Out of scope

- Multi-tenant hosting by the official deployment (each person runs their own).
- Providers other than Groq and OpenAI.
- Deployments without a Route 53 domain.

## Acceptance

1. `git grep` for the official account id, domain, GitHub owner and SSO profile returns only `docs/tasks/` hits.
2. The official dev and prd deploy and keep working (`deploy-dev` and `deploy-prd` green), with `terraform plan` showing no changes against the current state.
3. A scratch self-host from a fresh clone, following only `self-host/README.md` with the skill, ends with a working web sign-in and a desktop dictation through "Use your own server". The run is logged in the PR, and the teardown leaves nothing behind.
4. The landing section and the desktop link, in es and en, light and dark, with screenshots at the 0014 sizes.
5. `ci`, `desktop-ci` windows and linux-check green.

## Approach

- Terraform takes the config through variables and a generated backend config; no values live in `.tf` files.
- The setup command is TypeScript in the monorepo, reusing the existing deploy scripts.
- Discovery uses a well-known file, chosen over asking the user for pool ids, because the user only types a domain.

## Database

None.

## Infra

- Official deployment: values move to the local config and GitHub Actions variables. The om-manager sets the repository variables. Terraform runs only on Sebastian's machine, where the crews run: the crew plans dev and prd after rebasing on 0015 and applies only if a plan is empty or exactly the expected change (nothing destroyed or replaced); anything else stops and goes to the om-manager.
- Scratch self-host verification: in the official account under a scratch subdomain and a separate state prefix, unless the om-reviewer proposes better, and fully destroyed afterwards. Cost under 1 USD.

## Design

The landing section and the desktop link follow 0010 and 0014. The desktop link stays secondary (Sebastian, 2026-10-22).

## Risks

- Moving values out of Terraform could plan replacements on the official stack; Acceptance 2 guards it.
- Setup on an account with different quotas or SES/Cognito limits; the guide names the prerequisites.
